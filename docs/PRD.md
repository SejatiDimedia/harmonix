## 1. Ringkasan Eksekutif

Kebanyakan demo agent berhenti di "bisa menjawab di kondisi ideal". Proyek ini sengaja dibangun untuk kondisi produksi: ada guardrail, approval gate, observability, eval otomatis, dan dokumentasi kegagalan nyata. Domain analisis data (text-to-SQL) dipilih karena risikonya jelas dan mudah didemokan: query berbahaya, data sensitif (PII), biaya token, dan kesalahan interpretasi hasil.

Sistem dirancang dengan filosofi **Zero-Cost First (100% Gratis)**: seluruh stack komputasi dapat berjalan penuh secara lokal offline (Ollama / FastEmbed / Docker) atau memanfaatkan cloud free-tier tanpa kartu kredit (Google Gemini API di Google AI Studio / Groq API), menjadikannya ideal untuk eksperimen, iterasi cepat, dan portofolio tanpa tagihan cloud/API.

Data Analyst Agent menjawab pertanyaan bahasa natural (Indonesia dan Inggris) dengan menulis SQL, menjalankannya secara aman terhadap PostgreSQL, lalu menyajikan tabel, grafik, ringkasan, serta sitasi SQL dan definisi metrik yang dipakai.

**Asumsi:** domain yang dipilih adalah data analyst agent. Struktur PRD ini dapat diadaptasi ke domain lain (customer support agent, asisten regulasi) dengan mengganti tool dan dataset.

## 2. Latar Belakang dan Masalah

**Masalah pengguna (persona bisnis):** tim non-teknis (operasional, marketing, finance) sering membutuhkan jawaban dari database, tetapi bergantung pada analis data sehingga lambat dan antre.

**Masalah pembangun (tujuan portofolio):** perekrut AI Agent Engineer mencari bukti bahwa kandidat mampu membangun sistem agentic yang andal, bukan sekadar notebook atau proof of concept. Bukti yang diminta: diagram arsitektur, studi kasus kegagalan produksi, strategi evaluasi, serta trade-off cost vs latency vs akurasi.

## 3. Tujuan dan Non-Tujuan

### 3.1 Tujuan

1.  Agent menjawab pertanyaan analitik bahasa natural dari PostgreSQL dengan akurasi terukur.
2.  Seluruh lapisan harness hadir dan terdokumentasi: context pipeline, tool, memory, orchestration, guardrail, observability.
3.  Setiap perubahan prompt atau harness divalidasi oleh eval otomatis di CI sebelum merge.
4.  Menghasilkan artefak wawancara: diagram arsitektur, log kegagalan, laporan eval, dan tulisan trade-off.
5.  Dapat dijalankan 100% gratis secara lokal (Ollama / FastEmbed) atau via Cloud Free-Tier (Gemini 2.0 Flash / Groq) tanpa ketergantungan API berbayar.

### 3.2 Non-Tujuan

- Bukan produk SaaS komersial: tanpa multi-tenant, billing, atau manajemen pengguna kompleks.
- Tidak membangun UI yang rumit; antarmuka minimal sudah cukup.
- Tidak melakukan fine-tuning model (hanya mendokumentasikan alasan kenapa tidak diperlukan).
- Tidak mendukung operasi tulis ke database (read-only secara default).
- Tidak memerlukan langganan API berbayar (OpenAI, Anthropic Claude berbayar) maupun infrastruktur cloud berbayar.

### 4.1 Skenario Kunci

1.  Rina bertanya; agent mengambil skema relevan, menulis SQL, menjalankan, lalu menampilkan tabel, grafik, penjelasan singkat, dan SQL yang dipakai.
2.  Rina meminta data berisi PII (email pelanggan); agent menyamarkan kolom sensitif atau menolak sesuai kebijakan.
3.  Agent menghasilkan query berat (full scan tabel besar); sistem meminta persetujuan manusia sebelum eksekusi.
4.  Pada percakapan panjang, pertanyaan lanjutan ("bagaimana kalau hanya Jakarta?") tetap koheren berkat memory dan context management.
5.  Task analisis panjang gagal di tengah jalan; sistem melanjutkan dari checkpoint terakhir tanpa mengulang langkah yang sudah selesai.

## 7. Kebutuhan Non-Fungsional

- **Kinerja:** TTFT di bawah 3 detik untuk pertanyaan sederhana (Cloud Free Tier / Ollama M-series); jawaban lengkap p95 di bawah 30 detik untuk pertanyaan biasa.
- **Biaya:** target biaya operasional dan inferensi adalah **USD 0,00 (100% Gratis)** menggunakan model lokal (Ollama / FastEmbed) dan/atau kuota Cloud Free Tier (Google AI Studio Gemini / Groq API) tanpa memerlukan kartu kredit.
- **Keamanan:** tidak ada operasi tulis ke database; secret tidak pernah masuk log atau trace; PII tidak dikirim ke LLM tanpa masking.
- **Keandalan:** task yang gagal dapat dilanjutkan dari checkpoint; retry bersifat idempoten.
- **Portabilitas:** seluruh sistem berjalan dengan satu perintah docker compose up.
- **Kualitas kode:** type hints penuh, asyncio, Pydantic untuk semua kontrak data, cakupan tes unit untuk komponen guardrail.
- **Aksesibilitas (WCAG 2.1 Level AA Compliant):** antarmuka web memenuhi standar aksesibilitas internasional WCAG 2.1 AA dengan rasio kontras teks normal minimal 4.5:1 (teks utama `#f5f4ef` 14.8:1, teks sekunder `#9c9990` 6.41:1 terverifikasi MCP antislop-contrast), non-teks dan focus ring minimal 3.0:1 (`#d97757` 5.85:1), navigasi keyboard penuh (`:focus-visible` 2px outline, Tab/Shift+Tab, tombol Escape untuk semua modal, `group-focus-within`), serta semantik ARIA lengkap (`dialog`, `tablist`/`tab`, `scope="col"`, `live-region`, dan `role="img"` dengan `aria-label` deskriptif pada elemen canvas).

#### Format Event SSE (`/v1/chat`):
- `event: step_start` -> payload: `{"step": 1, "action": "planning | tool_call", "details": ...}`
- `event: token` -> payload: `{"delta": "..."}`
- `event: approval_required` -> payload: `{"approval_id": "...", "sql": "...", "risk_reason": "..."}` (client pause)
- `event: audit_step` -> payload: `{"status": "auditing | passed | flagged", "confidence": 0.98, "badge": "Verified by Auditor", "critique": "..."}`
- `event: final_result` -> payload: `{"answer_text": "...", "sql_queries": [...], "tables": [...], "charts": [...], "citations": [...], "follow_up_suggestions": ["...", "...", "..."], "audit_result": {"status": "PASSED", "confidence": 0.98, "badge": "Verified by Auditor", "critique": "..."}, "metrics": {...}}`
- `event: error` -> payload: `{"message": "..."}`

## 12. Risiko dan Mitigasi

| **Risiko**                            | **Dampak**                          | **Mitigasi**                                                                                     |
|---------------------------------------|-------------------------------------|--------------------------------------------------------------------------------------------------|
| SQL salah tetapi terlihat meyakinkan  | Jawaban menyesatkan                 | Tampilkan SQL, validasi kewajaran hasil, eval execution accuracy, kalibrasi LLM-judge.           |
| Prompt injection lewat data/dokumen   | Agent melakukan aksi tak diinginkan | Perlakukan konten retrieval sebagai data, allowlist tool, DB read-only, tes adversarial di eval. |
| Rate-limit pada Cloud Free Tier       | Eksekusi agent terhenti             | LiteLLM model fallback otomatis ke Ollama lokal (`qwen2.5-coder`), backoff retry eksponensial.    |
| Auditor salah menandai (false positive)| Jawaban valid tertahan / latensi naik | Konfigurasi severity threshold, self-correction loop dibatasi 1x, dan fail-open graceful degradation (fallback ke disclaimer jika rate-limited). |
| Eval tidak stabil (non-deterministik) | CI gate gagal palsu                 | Temperature rendah (0.0), cache respons deterministik, ambang toleransi, fokus pada tren.        |
| Cakupan melebar                       | Proyek tidak selesai                | Patuhi prioritas P0/P1; P2 hanya jika waktu tersisa.                                             |
| Dataset terlalu sederhana             | Demo kurang meyakinkan              | Gunakan dataset e-commerce realistis (Olist) dengan multi-tabel dan data kotor alami.            |

## 13. Keputusan Desain (Jawaban Pertanyaan Terbuka)

1. **Dataset:** Menggunakan dataset publik **Olist Brazilian E-commerce** (multi-tabel pesanan, produk, pelanggan, pembayaran, wilayah) yang di-seed ke PostgreSQL lokal. Memiliki data kotor alami tanpa biaya lisensi.
2. **Penyedia LLM & Anggaran:** **USD 0,00 (100% Gratis)**. Arsitektur hybrid via LiteLLM: Google AI Studio (Gemini 2.0 Flash / 1.5 Flash) dan Groq (Llama 3.3 70B) untuk inferensi cepat via cloud free-tier, dengan fallback offline ke Ollama lokal (`qwen2.5-coder:7b` / `llama3.1:8b` / `deepseek-r1:7b`).
3. **Cakupan UI:** Antarmuka web modern berbasis **React 19, TypeScript, Tailwind CSS, Vite, Zustand, dan TanStack Query** (dibundle langsung ke mount statis FastAPI `src/api/static`) yang mampu merender stream SSE real-time, tabel interaktif, visualisasi grafik Chart.js dengan fitur *Pin to Live Dashboard*, dialog persetujuan berisiko (*human-in-the-loop approval gate*), modal observabilitas latensi/drift, dan badge status verifikasi auditor. Tracing internal dipantau via dashboard Langfuse lokal/cloud free.
4. **Framework Pembanding:** **LangGraph**. Merupakan framework orchestration agen paling banyak diminta pada lowongan kerja AI Agent Engineer saat ini.
5. **Target Deployment:** **Docker Compose lokal** (`docker compose up`) yang menjalankan FastAPI backend, PostgreSQL 16 + pgvector, dan Langfuse dalam satu perintah tanpa dependensi cloud berbayar.
6. **Strategi Multi-Agent:** Memilih arsitektur **Maker-Checker (Analyst Agent + Data Auditor Agent)** daripada memecah tool deterministik menjadi agent terpisah. Pendekatan ini memisahkan eksplorasi analitik dari audit kualitas independen, memanfaatkan prinsip *Model Diversity* (memakai model cloud 70B gratis seperti Groq Llama-3.3-70B / Gemini Flash saat Analyst memakai model lokal 7B) untuk mengeliminasi *shared blind spots* dan halusinasi angka.
7. **Manajemen Model Dinamis, Dual-Mode API Key Configuration, OpenRouter Free Tier & 9Router Gateway:** Sistem mendukung multi-provider switching (Ollama lokal, Groq Cloud, Gemini, OpenRouter Free Models, dan 9Router Local Smart Gateway) yang dapat diatur via endpoint API dan UI modal di header. Konfigurasi kredensial API key bersifat dual-mode: dapat dikonfigurasi melalui berkas `.env` (standar DevOps/Docker) maupun dimasukkan langsung lewat antarmuka UI modal di browser dengan fitur masking keamanan rahasia dan auto-sync persisten ke file `.env` tanpa restart server. OpenRouter memperluas akses ke varian model gratis tanpa kartu kredit, sementara 9Router bertindak sebagai local gateway cerdas dengan automatic 3-tier fallback dan RTK token compression untuk efisiensi prompt analitik data.
8. **Interactive Live BI Dashboard Canvas ("Pin to Dashboard"):** Pendekatan konvergensi antara Chatbot conversational dan BI Dashboard visual. Mengizinkan pengguna bisnis menyematkan widget visual (grafik & tabel) dari alur chat ke kanvas permanen per-sesi. Pembaruan data dijalankan dengan mengeksekusi ulang sanitized SQL query yang tersimpan langsung ke PostgreSQL tanpa perlu mengulang inferensi LLM, memastikan refresh data dashboard memiliki latensi sangat rendah (<50ms) dan biaya token USD 0,00.
9. **Executive Report Generator (PDF & CSV Export):** Menjawab kebutuhan distribusi dan pelaporan eksekutif siap cetak tanpa ketergantungan API pihak ketiga berbayar. Mengimplementasikan ekspor CSV langsung berstandar RFC 4180 untuk analisis data lanjutan di Excel/Sheets, serta stylesheet cetak eksekutif (@media print) yang mentransformasikan Live BI Dashboard menjadi dokumen PDF bergaya korporat (latar putih bersih, kontras cetak optimal, grafik beresolusi tinggi, dan metadata tata kelola SQL/Data Auditor).
10. **Bring Your Own Data (BYOD) - Session-Scoped Dynamic PostgreSQL Engine:** Memilih pendekatan konversi berkas Excel/CSV langsung menjadi tabel fisik PostgreSQL di schema `analytics` daripada pure in-memory (DuckDB/Pandas di RAM). Keputusan ini memberikan 3 keunggulan utama: (1) **Cross-Join Bebas Hambatan**: memungkinkan kueri analitik menggabungkan data file eksternal dengan data warehouse PostgreSQL yang sudah ada secara instan dan native, (2) **Persistensi Live BI Dashboard**: visualisasi chart dari data yang diunggah dapat disematkan ke Live Dashboard dan tetap berfungsi bahkan setelah refresh halaman, dan (3) **Tata Kelola Bersih**: data terikat pada masa hidup sesi percakapan (*session-scoped*) dan secara otomatis dihapus via `DROP TABLE CASCADE` saat sesi dihapus, menjaga integritas dan kebersihan database.
11. **Standardisasi Tabel Markdown & Intelligent Auto-Normalizer (FR-40):** Mengatasi isu format perbandingan dan pemeringkatan (*ranking*) yang kerap ditulis model AI sebagai teks berkolom dengan spasi manual tak beraturan. Mengombinasikan prompt guardrail ketat di level backend agent dengan normalizer client-side cerdas yang mendeteksi pola spasi, nama bulan, dan mata uang untuk mengonversinya menjadi tabel HTML semantik bertema dark enterprise secara deterministik.
12. **Aksesibilitas Penuh Standar Internasional WCAG 2.1 Level AA:** Menjamin aplikasi dapat diakses secara inklusif oleh seluruh pengguna profesional termasuk pengguna dengan disabilitas penglihatan atau pengguna keyboard-only. Memenuhi rasio kontras ketat (14.8:1 pada teks utama, 6.41:1 pada teks sekunder, 5.85:1 pada focus ring), navigasi keyboard menyeluruh dengan visible focus outline 2px, listener Escape pada seluruh modal dialog, dan deskripsi semantik ARIA lengkap pada tabel maupun elemen grafik Canvas.
13. **Automated Data Health & Outlier Profiling Engine (FR-41 - Fitur Selesai & Aktif):** Memilih pendekatan *deterministic statistical profiling* di backend (Pandas / SQL aggregates) alih-alih meminta LLM melakukan pemindaian dari nol. Keputusan ini menjamin 3 pilar: (1) **Kecepatan & Biaya Nol**: kalkulasi Z-score, IQR, null-rate, dan duplikasi selesai dalam <100ms tanpa memakan kuota token LLM (zero API cost), (2) **100% Akurat Tanpa Halusinasi**: metrik kualitas data dihitung secara matematis eksak, dan (3) **Instant Value & Engagement**: memberikan umpan balik kualitas data seketika begitu berkas diunggah, memandu pengguna awam dengan 3 tombol investigasi cepat tanpa harus bingung merancang prompt awal.
14. **Deterministic Prompt Prefix Caching Engine (FR-15 - Fitur Selesai & Aktif):** Mengoptimalkan konsumsi token dan latensi inferensi LLM hingga 60-80% penghematan biaya melalui penataan prefix prompt yang deterministik (instruksi dasar statis → skema tabel stabil → memori pgvector → riwayat percakapan), hashing skema tabel sesi di memory, serta injeksi ephemeral cache control breakpoint untuk provider Anthropic dan OpenRouter. Dilengkapi visualisasi badge `[X cached]` di UI frontend.
15. **Two-Stage Hybrid Retrieval & Cross-Encoder Reranker (FR-12 - Fitur Selesai & Aktif):** Mengimplementasikan pipeline pencarian metrik bisnis dua tahap: Tahap 1 kandidat FastEmbed ONNX (dense) + PostgreSQL trigram/BM25 (sparse) dengan Reciprocal Rank Fusion (RRF k=60), dilanjutkan Tahap 2 Cross-Encoder Reranker lokal via FlashRank ONNX (`ms-marco-TinyBERT-L-2-v2`, 3.2MB) tanpa biaya cloud API untuk presisi semantik optimal terhadap sinonim dan kueri bisnis multi-kata.
16. **Working Memory & Scratchpad Engine untuk Long-Running Tasks (FR-18 - Fitur Selesai & Aktif):** Membedakan short-term memory (turn percakapan), long-term memory (few-shot pgvector), dan working memory (whiteboard aktif eksekusi). Agen analitik dapat memanggil tool `scratchpad` (`set`, `append`, `get`, `list`, `clear`) untuk menyusun rencana kerja bertahap, melacak hipotesis anomali data, dan mencatat angka kalkulasi perantara. State dipersistensikan secara eksternal ke file `data/scratchpads/{task_id}.json` dan kolom `working_memory` PostgreSQL (`analytics.agent_tasks`), disuntikkan secara dinamis di akhir system prompt agar tidak membatalkan prefix caching, serta disajikan di frontend dalam kartu interaktif *"Catatan Kerja Agen (Scratchpad)"* pada accordion flow pengambilan data.
17. **Sub-Agent Swarm & Planner-Executor Multi-Agent Architecture (FR-04 - Fitur Selesai & Aktif):** Memecah penyelesaian tugas analitik kompleks multi-langkah menggunakan arsitektur Orchestrator-Workers. Terdiri dari Planner Agent (menganalisis kompleksitas dan merancang ExecutionPlan DAG), Specialist Sub-Agents (SQL Specialist, Calculation Specialist, Visualization Specialist), Synthesizer Agent (mengonsolidasikan temuan menjadi laporan bisnis eksekutif utuh), dan Data Auditor Agent (verifikasi kualitas independen Maker-Checker). Disertai perbandingan jujur terhadap Single-Agent: Swarm mengeliminasi kegagalan context congestion dan loop terjebak pada kueri rumit dengan trade-off peningkatan konsumsi token (~25-40%) dan latensi antar-langkah.
18. **Air-Gapped Docker Container Sandbox untuk Eksekusi Python Tool (FR-26 - Fitur Selesai & Aktif):** Memperkuat keamanan eksekusi kode analitik Python (`calculate`) menggunakan isolasi ganda (defense-in-depth): (1) Pemeriksaan AST in-process (`PythonASTSecurityValidator`) yang melarang impor berbahaya (`os`, `sys`, `subprocess`, `socket`, `eval`, `__builtins__`), dan (2) Isolasi container Docker fisik nir-jaringan (`--network none`, batas memori 128 MB, CPU 0.5 core, read-only root filesystem, dan drop seluruh Linux capabilities `--cap-drop ALL`). Dilengkapi `SandboxManager` cerdas yang mendeteksi ketersediaan Docker daemon dalam <1.5 detik dan melakukan *graceful degradation* ke subprocess AST lokal jika Docker sedang tidak berjalan, menjaga reliabilitas sistem 100% tanpa crash.
19. **Batch Processing API & Bulk Asynchronous Query Engine (FR-42 - Fitur Selesai & Aktif):** Memfasilitasi kebutuhan analitik data skala perusahaan di mana ratusan pertanyaan bisnis diproses secara terjadwal/offline tanpa membebani antarmuka chat interaktif. Menggunakan antrian asinkronus dengan kontrol konkurensi (`asyncio.Semaphore`) untuk stabilitas kuota inferensi, endpoint pemantauan status transparan (`GET /v1/batch/{batch_id}`), serta ekspor dwiformat standar: JSONL untuk pipeline data rekayasa dan RFC 4180 CSV untuk laporan spreadsheet eksekutif.
20. **Distributed Task Queue, Background Worker & Bulk Analytics UI (FR-43 & FR-44 - Fitur Selesai & Aktif):** Keputusan rekayasa produksi untuk memisahkan beban komputasi analitik asinkronus (Batch Processing dan Multi-Agent Swarm) dari HTTP web server FastAPI. Menggunakan pendekatan *Zero-Cost Dual Adapter*: transactional PostgreSQL queue (`FOR UPDATE SKIP LOCKED`) yang hemat memori tanpa dependensi daemon tambahan untuk lingkungan lokal/single-node, opsi Redis Queue (RQ) untuk skalabilitas multi-worker horizontal di lingkungan kluster produksi, worker daemon mandiri dengan auto-retry exponential backoff dan Dead-Letter Queue (DLQ), serta antarmuka visual Bulk Analytics Runner di web UI.
21. **Interactive Chart-to-Chat Drill-Down Engine (FR-48 - Fitur Selesai & Roadmap Aktif):** Memilih pendekatan konvergensi interaktif langsung pada kanvas visual daripada mengandalkan pengetikan manual ulang oleh pengguna. Pengguna dapat mengklik elemen data grafik (batang, irisan, titik) untuk memunculkan popover aksi investigasi cepat yang mempertahankan SQL induk dan dimensi terpilih ke dalam sesi chat, memangkas friksi eksplorasi anomali secara dramatis. Dokumen detail: `docs/PRD_FR48_CHART_DRILLDOWN.md`.
22. **Automated Metric Watchdog & Threshold Alerting Engine (FR-49 - Fitur Selesai & Roadmap Aktif):** Memisahkan eksekusi pemantauan reguler dari model bahasa (LLM). Pengecekan terjadwal dijalankan murni menggunakan query SQL langsung ke PostgreSQL via AST Guardrail berbiaya USD 0,00. Pemanggilan agen inferensi LLM hanya dipicu secara selektif (*event-driven on breach*) untuk menyusun analisis kausalitas 3-kalimat sebelum notifikasi dikirimkan ke Slack/Discord/Teams dan Notification Center in-app. Dokumen detail: `docs/PRD_FR49_METRIC_WATCHDOG.md`.
